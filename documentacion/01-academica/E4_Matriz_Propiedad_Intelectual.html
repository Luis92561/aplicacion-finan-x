1. Para qué sirve esta matriz

Antes de definir las condiciones de uso del software (Evidencia 5) hay que saber qué hay dentro y de quién es cada parte. Esta matriz responde a tres preguntas:

  • ¿Qué parte de FINAN-X es original del equipo?
  • ¿Qué parte es de terceros y con qué licencia se usa?
  • ¿Alguna de esas licencias condiciona lo que el equipo puede hacer con su propio software?
Conclusión principal

Todas las librerías que forman parte del software entregado usan licencias permisivas (MIT, ISC, BSD, Apache). Ninguna obliga a publicar el código propio ni impide su uso comercial, así que el equipo conserva la titularidad y puede licenciar el producto con las condiciones que decida (Evidencia 5). La única licencia copyleft del proyecto corresponde a PlantUML, que es una herramienta de documentación que no se distribuye con el software: se ejecutó para generar los diagramas.

Caso de PlantUML: por qué su GPL-3.0 no contagia el proyecto

PlantUML es la única pieza con licencia copyleft fuerte (GPL-3.0). Su obligación es que, si se distribuye el programa o un producto derivado, se libere el código en los mismos términos.

Aquí no se distribuye ni se enlaza con el software: es una aplicación independiente que se ejecuta desde la línea de comandos con java -jar plantuml.jar para transformar archivos de texto .puml en imágenes .svg. Lo que se distribuye son los SVG resultantes, que son obra del proyecto, no código de PlantUML. Es el mismo caso que usar un editor de texto con licencia GPL para escribir un documento: el documento no queda sujeto a esa licencia.

Uso del servicio: sin datos de terceros

El proyecto no consume ninguna API externa ni descarga conjuntos de datos ajenos: no hay llamadas de red salidas del sistema (las únicas direcciones que aparecen en el código son de localhost). Tampoco usa fuentes tipográficas, iconos ni plantillas de terceros: la tipografía es la del sistema y los iconos son caracteres emoji estándar.

9. Cómo se verificó

Las licencias no se copiaron de una página web: se leyeron del árbol de dependencias instalable del propio proyecto, que es la fuente autoritativa.

# Analiza backend/package-lock.json y frontend/package-lock.json
node deep-docs/_generar_licencias.mjs

El script recorre cada paquete, lee su campo de licencia, agrupa por tipo y avisa si encuentra una licencia copyleft o una sin declarar. Su salida es la que alimenta las tablas de este documento.

Mantener esta matriz actualizada

La matriz debe revisarse cuando se añada o actualice una dependencia. Volver a ejecutar el script y regenerar este documento es suficiente; si aparece una licencia nueva, quedará reflejada automáticamente.
